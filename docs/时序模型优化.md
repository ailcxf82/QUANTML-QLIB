## 一、文档定位

本文档回答一个问题：**在当前工程（LightGBM 日频主链路、Sharpe ≈ 2.3）下，引入时序模型（LSTM/GRU/Transformer）与分钟级数据，能在哪些方面、以何种方式带来可验证的提升？**

**核心结论（先读）：**

- 当前瓶颈不在「更好的 LGBM 调参」，而在**信息维度**（日频 → 分钟）与**执行真实性**（标签/撮合/滑点对齐）。
- **最高 ROI 路径**：分钟数据先做**日级聚合因子**喂现有 LGBM，而非立刻上复杂时序模型。
- 时序模型（`dataset_type: ts`）应在独立 freq / lab 中实验，通过 walk-forward + 超额 + 换手门禁后再考虑 ensemble 上线。

## 三、七大提升维度与具体案例

### 维度 I：Alpha 信号层（预期 ICIR +0.05 ~ +0.10）

当前因子几乎全是日级聚合。分钟数据可新增 `intraday` 因子组（建议 `python/features/intraday.py`）：

| 因子族 | 案例 | 表达式思路 | 业务含义 |
|--------|------|------------|----------|
| 日内时段动量 | `OPEN30_RET` | 9:30–10:00 涨幅 | 开盘动量/反转 |
| | `TAIL30_RET` | 14:30–15:00 涨幅 | 尾盘机构行为 |
| 跳空缺口 | `GAP_OPEN` | open/prev_close - 1 | 缺口延续/回补 |
| | `GAP_FILL` | (close-open)/(prev_close-open) | 缺口填充率 |
| 已实现波动 | `RV_INTRADAY` | Σ(min_ret²) | 比 STD20 更纯净 |
| 成交量形态 | `VOL_AM_RATIO` | 早盘量/全天量 | U 型/L 型/反 L 型 |
| VWAP 偏离 | `CLOSE_VWAP_DEV` | close/VWAP - 1 | 拉尾盘嫌疑 |
| 价格分形 | `HIGH_TIME_IDX` | 日内最高点出现时段 | 早高 vs 晚高 |

**落地方式（P0，不改模型）：**

1. 分钟 bar 聚合为日频特征列，注册到 `AlphaDef(group="intraday")`。
2. 新建 `configs/freq/daily_plus_intraday.yaml`，在 `model_meta.feature_groups` 中加入 `intraday`。
3. 与 `daily_retrain` 同 seed、同 `daily_vol_target` 策略做 A/B。

**验收：** OOS IC 提升 ≥ 0.005 且 TopK 超额同步提升（见 lessons：IC ≠ Alpha）。

### 维度 II：标签精细化（消除撮合偏差）

| 问题 | 方案 | 配置建议 |
|------|------|----------|
| close-to-close 偷看 T+1 开-收 | open-to-open 或 VWAP-to-VWAP | 已有 `daily_t1_open.yaml`；分钟就绪后改 `daily_vwap_label.yaml` |
| 单日噪声 | 5 日累计 label | 已有 `daily_5d_label.yaml` |
| 涨跌停日 label 失真 | 9:25 一字板标记 NaN | `DropnaLabel` + 分钟集合竞价字段 |
| 与 Sharpe 目标对齐 | IR-label：return / RV_30min | 独立 model yaml，勿改 `base.yaml` |

**标签-撮合对齐原则（W1 延伸）：**

```
label 起点字段  ==  deal_price  ==  实盘下单价口径
```

示例（分钟数据就绪后）：

```yaml
# configs/freq/daily_vwap_label.yaml（平行配置，勿覆盖 base）
label:
  - "Ref($vwap_open30_qfq,-2)/Ref($vwap_open30_qfq,-1)-1"
backtest:
  exchange_kwargs:
    deal_price: "$vwap_open30_qfq"
```

**验收：** 长 OOS（≥ 120 交易日）下，与 `daily_retrain` 的 \|ΔSharpe\| < 0.15；若 open/VWAP 显著更优，再考虑切主链路。

### 维度 III：时序模型架构（LSTM / GRU / Transformer）

当前配置（`configs/models/lstm.yaml` 等）：

- `dataset_type: ts`，`step_len: 20`，`freq_key: 1day`
- `feature_groups: [momentum, volume, technical]`（约 20 维）

**日频时序（现有框架内优化）：**

| 项 | 建议 |
|----|------|
| step_len | 20 → 40/60（更长记忆） |
| 特征 | 保持量价技术组；基本面时序变化慢，可不加 |
| 损失 | MSE → Huber（独立 yaml 对照） |
| 与 LGBM 融合 | **rank-space**：`0.6×lgbm_rank + 0.4×gru_rank`（优化清单 W3） |

**分钟频时序（数据就绪后）：**

| 架构 | step_len | 说明 |
|------|----------|------|
| LSTM/GRU | 240（1 日）或 480（2 日） | 需 GPU；batch 适当减小 |
| Transformer | 240 + 多尺度 patch | `d_model: 128`, `nhead: 8`, `num_layers: 4` |
| PatchTST / iTransformer | patch 切分 | 长序列效率更高，可作为 lab 探索 |
| TFT | 已知未来变量 | 财报日、指数开盘等 |
| 多任务头 | 30min / 2h / 1d | 共享 backbone，降 label 噪声 |

**新建配置示例：**

```
configs/models/transformer_intraday.yaml   # step_len=240, freq_key=1min
configs/freq/minute.yaml                   # data_ready=true 后启用
```

**验收门禁（与 lessons 一致）：**

- Walk-forward ≥ 4 fold
- OOS test ≥ 120 交易日
- 评估策略 = 部署策略（`daily_vol_target.yaml`）
- IC 升但超额跌 → **红灯，禁止上线**

## 八点五、LGBM × 时序模型分工设计（核心方法论）

> **一句话原则**：最科学的分工不是「模型差异」，而是「**信息源差异**」。LGBM 吃浓缩因子做截面专家，时序模型吃原始序列做路径专家。

### 8.5.1 文献依据（Qlib 官方 benchmark · CSI300 · 20 seed 均值）

| 模型 | Alpha158（手工因子） IC / ICIR | Alpha360（原始序列） IC / ICIR |
|------|--------------------------------|-------------------------------|
| **LightGBM** | **0.0448 / 0.366** | 0.0400 / 0.304 |
| GRU | 0.0315 / 0.245 | **0.0493 / 0.377** |
| LSTM | 0.0319 / 0.246 | 0.0466 / 0.347 |
| Transformer | 0.0290 / 0.232 | 0.0494 / 0.391 |
| DoubleEnsemble（LGBM-base） | **0.0521 / 0.422** | 0.0390 / 0.295 |
| TCTS（GRU-base） | — | 0.0508 / 0.393 |
| TRA（时序路由） | 0.0440 / 0.354 | 0.0485 / 0.379 |
| HIST（图+时序） | — | **0.0522 / 0.353** |

**关键结论：**

1. LGBM 在**结构化因子**上明显优于时序模型（信息已浓缩，序列建模无增量）
2. 时序模型在**原始 OHLCV 序列**上明显优于 LGBM（路径依赖是 LGBM 学不到的）
3. DoubleEnsemble（同质 LGBM 多模型）能在 Alpha158 把 IC 从 0.0448 推到 0.0521
4. TRA / HIST 在 Alpha360 上 Sharpe ≥ 1.13（CSI300 2017-2020 OOS），超 LGBM 0.50
5. 学术综述（arxiv 2505.23084 等）一致认为 **LSTM + LGBM stacking 提升 10–15% 精度**

参考文献：

- Qlib benchmarks（[microsoft/qlib examples/benchmarks](https://github.com/microsoft/qlib/blob/main/examples/benchmarks/README.md)）
- DoubleEnsemble（Chuheng Zhang et al.，`qlib.contrib.model.double_ensemble`）
- TRA（Hengxu Lin et al.，`qlib.contrib.model.pytorch_tra`）
- HIST（Wentao Xu et al.）；TCTS（Xueqing Wu et al.）
- Arxiv 2505.23084（LSTM+LightGBM+CatBoost hybrid，10-15% 误差降低）
- hal-02311104（Ensemble Learning in Multifactor Equity，rank IC 0.05→0.11）
- Arxiv 2210.12462（Deep Multi-Factor with Graph Attention，deep factor 理论基础）

### 8.5.2 当前工程的错位（必须修正）

```yaml
# configs/models/lstm.yaml / gru.yaml / transformer.yaml
feature_groups:
  - momentum         # ← 与 LGBM 完全相同
  - volume           # ← 与 LGBM 完全相同
  - technical        # ← 与 LGBM 完全相同
```

**问题：** 时序模型吃的是「压缩好的因子」而非原始序列，相当于让 LSTM 学一个已经被 LGBM 吃得很好的输入空间。这是 Alpha158 上时序模型 IC < LGBM 的根本原因，也是当前工程 ensemble 价值未释放的瓶颈。

**修正：** 新增 `feature_groups: [raw_ohlcv]`（仅 6 维 OHLCV，让序列建模发挥作用），独立 yaml 不破坏现有。

### 8.5.3 五层融合方案（从松到紧）

| Level | 方式 | 表达式 | 优势 | 风险 |
|-------|------|--------|------|------|
| **L1** | Rank 平均 | `0.7×rank(p_lgbm) + 0.3×rank(p_ts)` | 稳健、与 lessons P1 一致（rank-space） | 静态权重，市场切换时不灵 |
| **L2** | IC 动态加权 | `w_i ∝ ICIR_i_20D` | 自适应 regime 切换 | 需稳健的 IC 估计窗口 |
| **L3** | Stacking + meta-MLP | OOF 预测 → MLP 学融合权重 | 学界标准；arxiv 多篇证明 +10-15% | 复杂度高，需大量 OOF 数据 |
| **L4** | 残差学习 | `final = p_lgbm + λ × g_ts(残差)` | 时序只补 LGBM 学不到的 | 残差噪声大，易过拟合 |
| **L5** | Deep Factor（不输出分数） | 时序 hidden state → LGBM 新特征 | 一个最终模型，运维简单 | 时序模型不可独立评估 |

**默认推荐：** L1 起步 → 稳定后升 L2 → 若数据量足够再 L3。L4/L5 作为探索性 lab。

### 8.5.4 三种分工架构对比

**架构 A：信息源分工 + Rank 融合（推荐 P1）**

```
┌──────────────────┐                    ┌──────────────────┐
│ LightGBM 主力    │                    │ GRU/Transformer  │
│ 输入: 158+ 因子  │                    │ 输入: 60×6 OHLCV │
│ (含 intraday 聚合)│                   │ (原始序列)       │
└────────┬─────────┘                    └────────┬─────────┘
         │ pred_lgbm                             │ pred_ts
         └──────────────┬────────────────────────┘
                        ▼
              ┌──────────────────┐
              │ L1: rank 平均    │
              │ 0.7×lgbm + 0.3×ts│
              └─────────┬────────┘
                        ▼
                  final score
```

**架构 B：Deep Factor 单模型（推荐 P2）**

```
┌──────────────────────────┐
│ 分钟时序模型 (Transformer)│
│ 输入: 240×6 分钟序列     │
│ 输出: 16-32 维 hidden    │  ← 作为新特征
└────────────┬─────────────┘
             ▼
┌──────────────────────────┐
│ LightGBM 主力 (唯一上线模型)│
│ 输入: 原 158 因子 + 16 维 │
│       deep factor         │
│ 输出: pred                │
└──────────────────────────┘
```

**架构 C：残差路径（探索性 lab）**

```
Stage 1: pred_lgbm ← LGBM(标量因子)
Stage 2: r = label - pred_lgbm
Stage 3: pred_ts ← GRU(原始序列) 拟合 r
Stage 4: final = pred_lgbm + λ × pred_ts, λ ∈ [0.1, 0.5]
```

ALPHAS: list[AlphaDef] = [
    AlphaDef(name="OPEN",  expr="$open_qfq/Ref($close_qfq,1)",  group="raw_ohlcv",

             description="标准化最高价"),
    AlphaDef(name="LOW",   expr="$low_qfq/Ref($close_qfq,1)",   group="raw_ohlcv",

    AlphaDef(name="CLOSE", expr="$close_qfq/Ref($close_qfq,1)", group="raw_ohlcv",

### 8.5.7 红线（与既有 lessons 兼容）

| ❌ | 原因 | 参考 |
|----|------|------|
| 时序模型用与 LGBM 相同的 `feature_groups` | 信息源未分离 → ensemble 冗余 | 本节 8.5.2 |
| 直接 raw score 加权（不做 rank） | 尺度差异；lessons 2026-05-11 P1+P2 已踩坑 | `lessons/2026-05-11_p1p2_neutralize_pitfall.md` |
| 时序模型独立上线替换 LGBM 主力 | OOS 未稳定前 IC 涨 ≠ 超额涨 | 同上 |
| Stacking 不做 walk-forward OOF | meta-MLP 过拟合 | 学界共识 |
| 仅用单 seed 比较 LGBM vs 时序模型 | benchmark 都是 20 seed 均值 | Qlib README |

### 8.5.8 验收门禁（在 §七 基础上追加）

| 维度 | 阈值 |
|------|------|
| 时序模型与 LGBM 的 pred 相关性 | ρ < 0.85（太高说明信息源未分离） |
| Ensemble OOS Sharpe | ≥ max(LGBM 单模型, 时序单模型) + 0.05 |
| Rank IC 提升 | ≥ +0.003（单模型 IC 0.04 → ensemble 0.043+） |
| 换手率 | 与 LGBM 主力 ±20% 以内，超出需重新调融合权重 |
